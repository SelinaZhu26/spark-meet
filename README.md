# ⚡ Spark

Strangers around you often share your hobbies, but you walk past each other and never find out. Spark is the missing spark: switch it on, put your phone away, and both phones buzz when someone you'd click with is a few steps away.

- `backend/`: Rust (axum, sqlx, reqwest). Matching, Gemini, ElevenLabs, OAuth integrations, push.
- `app/`: Expo (React Native, expo-router). Sign-in, the ON switch, spark cards, chat.

## How it works

```
phone (Spark ON) ── POST /presence/ping {lat, lng} ──▶ backend
                                                        │
             Tiger Data: INSERT ping, ST_DWithin 30 m, last 2 min ──▶ nearby user ids
                                                        │
      Supabase: claim the pair (UNIQUE(user_a, user_b)) ──▶ only one phone wins
                                                        │  (scored in the background)
       1. cosine similarity of Gemini embeddings < floor? ──▶ fizzle, no LLM call
       2. Gemini verdict (structured JSON) ──▶ score ≥ 70 and an allowed mode? ──▶ SPARK
                                                        │
       Expo push to both phones, plus delivery on each phone's next ping
                                                        │
       card: score, shared interests, reason, icebreaker (no name, no photo, no location)
                                                        │
       both tap "Wave" ──▶ profiles revealed, chat opens
```

Both phones report pings, so both "see" the encounter. The database's unique constraint on the ordered pair hands out exactly one claim, so the similarity calculation runs once per pair no matter which phone reports first.

## Hackathon tracks

| Track | What Spark does with it |
| --- | --- |
| **Gemini** | `generateContent` with a `responseSchema` returns structured JSON: `shared_interests`, `reason`, `score`, `mode` (`friends` / `dating` / `none`, restricted to pools both people opted into) and `icebreaker`. Reasoning fields are ordered before the score. `gemini-embedding-001` embeds each interest profile for a deterministic cosine-similarity prefilter, so obviously unrelated pairs never cost an LLM call. See `backend/src/services/gemini.rs`, `matcher.rs`. |
| **Tiger Data** | Location pings are time-series data in a TimescaleDB hypertable (15-minute chunks, 1-hour retention policy). "Who's within 30 m of me in the last 2 minutes" is a PostGIS `ST_DWithin` query over a GiST index. See `backend/migrations_pings/`, `src/db/pings.rs`. |
| **ElevenLabs** | Spark's signature buzz is generated by the sound-effects API (`GET /audio/spark.mp3`, cached after first generation). Icebreakers can be read aloud with text-to-speech as an accessibility option. See `src/services/elevenlabs.rs`, `src/routes/audio.rs`. |
| **Vultr** | `backend/Dockerfile` builds a slim image (sqlx offline mode, no DB needed at build time). |
| **GoDaddy domain** | Point the domain at the Vultr box and set `PUBLIC_BASE_URL`; OAuth callbacks are built from it. |

## Safety

- **Location never leaves the backend.** No endpoint returns coordinates or distances. Pings are deleted after an hour (retention policy plus a prune task) and immediately when you switch Spark off.
- **Mutual opt-in.** A spark card shows only what you share, the reason and an icebreaker. Names, photos and bios are revealed, and chat opens, only after both people wave. A one-sided wave is never shown to the other person.
- **Separate pools.** Friends and dating are separate. A dating spark requires both people to have opted into dating, enforced in code (`shared_modes`, `pick_mode`), not just in the prompt.
- **No identifying data goes to Gemini.** Interest profiles contain interests, bio and linked-account summaries, never names. Profiles are delimited and the model is told to ignore instructions inside them.
- **Linked accounts are a one-time snapshot.** OAuth tokens are used once to read top artists or recent activities, then discarded.
- Supabase tables have row-level security enabled with no policies, so the auto-generated Supabase REST API can't read them. Only the backend (table owner) can.

## Running locally

### Database

```sh
docker compose up -d   # TimescaleDB + PostGIS on localhost:5544, stands in for both Supabase and Tiger Data
```

### Backend

```sh
cd backend
cp .env.example .env   # fill in SUPABASE_URL, GEMINI_API_KEY, optionally ElevenLabs/Spotify/Strava
cargo run              # runs migrations on startup, listens on :8080
cargo test
```

The sqlx query cache in `.sqlx/` lets the backend build without a database. After changing a query, run `cargo sqlx prepare` against a migrated database and commit `.sqlx/`.

Production: `DATABASE_URL` is the Supabase **session pooler** connection string (the transaction pooler breaks prepared statements), and `PINGS_DATABASE_URL` is the Tiger Data service. Leaving `PINGS_DATABASE_URL` unset keeps pings in the main database (without TimescaleDB the table stays a plain table).

### Supabase setup

1. **Authentication → Providers:** enable Google (and Phone with an SMS provider if you want phone sign-in). Email is on by default.
2. **Authentication → URL configuration → Redirect URLs:** add `spark://auth-callback` and `exp://**` (Expo Go).
3. **Authentication → Emails → Magic Link template:** include `{{ .Token }}` so emails contain the 6-digit code the app asks for.
4. Backend: set `SUPABASE_URL`. Tokens are verified against the project's JWKS. For projects still on the legacy JWT secret, set `SUPABASE_JWT_SECRET` instead.

### App

```sh
cd app
npm install
cp .env.example .env   # EXPO_PUBLIC_API_URL must be reachable from the phone (LAN IP or deployed URL)
npx expo start
```

**Expo Go** runs everything except background location and push notifications: Spark works while the app is open, and sparks arrive as local notifications on the next ping. For the full experience (pocket mode, push), use a development build:

```sh
npx expo run:android            # or: npx expo run:ios (needs Xcode)
npx eas-cli@latest build --profile development   # cloud build, no Xcode needed
```

Push tokens need an EAS project id (`npx eas-cli@latest init` adds it to `app.json`).

### Linked accounts

Register `<PUBLIC_BASE_URL>/integrations/spotify/callback` and `<PUBLIC_BASE_URL>/integrations/strava/callback` with each provider, then set the client id and secret env vars. Spotify only accepts HTTPS or loopback redirect URIs, so test against the deployed domain (or a tunnel). The app's return deep links must match `APP_REDIRECT_ALLOWLIST` (default `spark://,exp://`).

## API

All routes except `/health`, `/audio/spark.mp3` and the OAuth callback need `Authorization: Bearer <Supabase access token>`.

| Method | Path | |
| --- | --- | --- |
| `GET` | `/me` | Profile (created on first call), linked accounts, available integrations |
| `PUT` | `/me` | Update profile; re-embeds the interest profile |
| `PUT` | `/me/push-token` | `{ token }` Expo push token |
| `POST` | `/presence` | `{ active }` the ON/OFF switch; OFF deletes your pings |
| `POST` | `/presence/ping` | `{ latitude, longitude, accuracy? }` → `{ sparks }` not yet delivered |
| `GET` | `/sparks` | Your sparks, newest first |
| `GET` | `/sparks/{id}` | One spark |
| `POST` | `/sparks/{id}/wave` | Wave; returns the spark (with `other` once mutual) |
| `GET` | `/sparks/{id}/messages?after=` | Chat history after a message id (connected sparks only) |
| `POST` | `/sparks/{id}/messages` | `{ body }` |
| `GET` | `/sparks/{id}/icebreaker.mp3` | Icebreaker read aloud (ElevenLabs) |
| `GET` | `/audio/spark.mp3` | The Spark buzz (ElevenLabs sound effect) |
| `GET` | `/integrations/{provider}/connect?return_to=` | `{ url }` to open in a browser |
| `GET` | `/integrations/{provider}/callback` | OAuth redirect target; bounces back to `return_to` |
| `DELETE` | `/integrations/{provider}` | Unlink |

## Deploying to Vultr

```sh
docker build -t spark-backend backend
docker run -d --restart unless-stopped -p 80:8080 --env-file backend/.env -v spark-cache:/app/cache spark-backend
```

Put Caddy or another TLS proxy in front for HTTPS on your domain.
